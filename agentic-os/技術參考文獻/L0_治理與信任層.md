## 💰 需採購 / 外部授權

- 合格可信時間戳服務 (RFC 3161 TSA) 或等效外部錨定服務：用於定期為稽核鏈 Merkle root 做外部、獨立的時間戳證明，防止內部（含資料庫最高權限管理者）事後竄改整條鏈而不被發現；因需「外部、獨立、可被第三方信任」，無法自架，僅列為最高保證等級的選配採購項
- 雲端 Object Lock 服務（如 AWS S3 Object Lock）或 MinIO 官方後繼商業產品 AIStor Enterprise：MinIO 主 repo 已於 2026-04-25 封存並標示不再維護（原授權 AGPLv3），若團隊不打算自行承擔 Ceph 叢集維運與合規認證成本，可列為不自架、直接採購的務實選項，優先順序低於前一項時間戳服務

## 🏗️ 自研開發 Spec

Agent Registry Service 採 A2A AgentCard schema 為資料格式基礎（name/description/version/url/skills/capabilities/securitySchemes/security/provider/extensions/signature），以 extensions 掛載 owner/lifecycle_state/approval_record 等治理欄位（無現成 Registry 伺服器可用，需自建輕量服務）。Identity & Credential Issuer 整合 SPIRE（workload attestation+SVID）與 Keycloak（RFC 8693 token exchange，簽發帶 act/sub claim 的委任短效 token）。PDP 以 OPA 為主、Cedar 為效能備選，PEP 用 Casbin in-process；OpenFGA 處理 ReBAC 關聯授權。Audit Chain Writer 將 tool call 事件雜湊串接寫入 immudb，Merkle Anchoring Service 定期產生 root、可選錨定外部 WORM/TSA。Observability 以 OTel GenAI semantic conventions 埋點並以 trace_id/event_id 關聯稽核鏈。核心資料模型：AgentIdentity（spiffe_id/svid/issued_at/expires_at）、DelegatedToken（RFC 8693，sub/act/scope/exp）、PolicyDecisionRecord（policy_version/decision/matched_rule）、AuditEvent（append-only，含 prev_hash 形成 hash chain）、AgentRegistryEntry（對應 AgentCard 欄位+extensions）、MerkleAnchorRecord。

## ❌ 反模式（要避免）

- 不要再推薦 MinIO 作為新的自架 WORM 稽核儲存方案——主要 repo 已於 2026-04-25 封存、標示不再維護（原授權 AGPLv3），應改評估 Ceph RGW 或雲端 Object Lock/AIStor
- 不要把 BSL/ELv2 (source-available) 授權專案直接標記為「開源」而不附使用限制說明——immudb 為 BSL 1.1、Phoenix 為 ELv2（明確禁止受管服務轉售），兩者均非 OSI 開源
- 不要只憑單一 vendor 的效能宣稱（如 AWS 聲稱 Cedar 比 Rego 快 42-60 倍）就寫入正式 spec 作為效能保證，未經第三方或自行 benchmark 驗證前僅能視為參考
- 不要讓每次 tool call 都強制跳轉集中式 PDP 造成高延遲——高頻場景應改用 embedded library (Casbin) 做 in-process 決策
- 不要用長效靜態密鑰做 agent-to-agent 或 agent-to-API 身分驗證——應採短效可自動輪替憑證 (SVID/OAuth token exchange)
- 不要手刻 (hand-roll) hash chain 卻不做定期外部錨定——純內部 append-only log 若無外部 Merkle root 錨定，理論上仍可被擁有資料庫最高權限者竄改，稽核可信度打折扣
- 不要把規則式策略引擎 (OPA/Cedar) 與關聯式授權 (OpenFGA) 當作互斥的替代選項——兩者解決不同問題，大型系統通常併用
- 不要僅憑「普遍認知」而不查證官方 LICENSE 檔案原文就把授權當作已確認事實寫入正式合約或法遵文件——OPA/Cedar/A2A 的 Apache-2.0 與 immudb 的 BSL 1.1、Phoenix 的 ELv2，皆是透過直接查核 LICENSE 原始檔案才能定案
- 不要略過「Agent Registry」獨立立項調查就直接進入實作——原始兩來源對此支柱研究均嚴重不足，仍缺乏成熟「可直接自架的 Registry 伺服器實作」，貿然開工仍有設計盲區
