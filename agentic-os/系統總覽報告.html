① Positioning

一句話定位

AIOS＝本地優先（local-first）的多代理「AI 員工」作業系統。每位 Agent 有身分卡、掛載技能（Skill）、配置工作流（Workflow）、長期記憶、獨立沙盒與成本上限；由三個本機 CLI 引擎執行，並由跨模型驗證閘把關輸出。

三支柱

🚂
支柱一

三引擎

CLAUDE_CODE 主力執行；CODEX 程式類／交叉驗證／電腦操控；GROK 檢索與草擬最快。全部以本機 CLI spawn 呼叫。

⚖️
支柱二

跨模型驗證閘

執行引擎 ≠ 驗證引擎，載入時強制（autoVerify 取對面）。判決 isApproved() 採 fail-closed（拒絕優先於通過）；驗證器可跨回合續命。

🔒
支柱三

引擎層限制

webSearch／computerUse／sendEmail／cloudWrite／shell／cloudEmbedding／sandbox 於程式碼層攔截（throw／拒絕），不靠模型自覺。

🏠 在地優先邊界 · ☁️ 兩個刻意雲端例外

邊界：Postgres／Redis／Qdrant／Docling 四個 Docker 服務全部只綁 127.0.0.1；後端與前端必須跑在主機（引擎要 spawn 主機 CLI）。

  • ① 記憶 embedding → 走 OpenRouter（語意索引用）
  • ② 語音轉錄 → 走 OpenAI Whisper（口述訓練；ADR 0006）

這兩項已在文件明載，不得擅自擴大。其餘資料與執行預設不離機。使用者授權的 Google／Microsoft／LINE 另屬整合連線。

② Hard Rules

五條紅線 違反即是 bug

系統不變量。任何功能與重構都不得弱化；改動須能證明零回歸。

RED LINE 01
⚖️ 跨模型驗證閘不可弱化
執行引擎 ≠ 驗證引擎，於 compileManifest() 載入時強制。判決 oracle 為 fail-closed：REJECTED 判定優先於 APPROVED。
RED LINE 02
🛡️ 安全與成本是硬約束
限制與預算在程式碼層攔截（throw／拒絕），不是只在 prompt 寫「請不要」。判不準時一律拒絕（fail-closed）。
RED LINE 03
🔏 紅線 redactor 永遠生效
任何記憶／技能／稽核內容落地前一律經 redactSecrets() 遮罩密鑰與個資，不受任何旗標影響。
RED LINE 04
✋ 技能永不自動確認
新／改的 Skill 一律停在 AWAITING_USER_CONFIRM，只有 FDE（TRAINER／OWNER）人工確認才 CONFIRMED 並可掛載。
RED LINE 05
👤 變更生效唯一路徑是 FDE
操作者（MEMBER）只能提案（ChangeProposal），不能讓任何變更生效。核准後才產生可回滾版本；駁回則目標物零變動。
🔴 fail-closed（閘門類）

限制、預算、核准、路徑守門 — 出錯就拒絕。寧可擋下，不可放行。

🟢 fail-safe（附屬類）

記憶沉澱、成本記錄、越矩提案、文件解析 — 出錯只 log，絕不可讓 run 失敗。

④ Execution Flow

核心執行流 — runAgent()

系統心臟在 src/engine/runner.ts。高風險未核准時完全不碰引擎、不燒錢；每步必經預算閘 → 執行 → 對面引擎驗證 → 記帳。

1🔍 找 Agent
依 ID 載入員工設定：引擎、限制、成本政策、風險等級、身分卡。
▼
2🚦 HITL 前置閘 requiresApproval()
riskTier === 'high' 且未真核准 → 建 Run AWAITING_REVIEW ＋ ApprovalRequest，直接 return。「真核准」＝ DB 有 status='APPROVED' 的 ApprovalRequest（不是傳個字串就算）。
▼
3📁 具現化 materializeAgent()
寫入 MyAgent/<dept>/<slug>/：agent.md、CLAUDE.md、skills／、memory／wiki、sandbox profile。
▼
4▶️ 建 Run RUNNING
執行紀錄落地，後續每步寫入 RunStep。
▼
5🧩 編譯 compileManifest()
此處強制 execute ≠ verify（autoVerify 取對面引擎）。組裝角色、限制、技能、記憶、成本政策。

⑤ Governance

治理模型 — 變更提案佇列

本輪核心產物（ADR 0003／0004）。操作者可參與，但只有 FDE 能讓變更生效。越矩偵測雙軌：硬攔截（決定性）＋ 語意審查（僅 HIGH 進佇列）。

❌ 駁回
目標物零變動 — 技能、限制、身分卡維持原狀。
⚠️ 誠實邊界：偵測不到的不要假造
  • shell／webSearch 由 claude --disallowedTools 在子行程內封鎖 — 我們的 process 看不到嘗試。
  • 沙盒是 OS 層 EPERM — 同樣不可見於主流程。
  • 硬攔截軌：決定性、免 LLM、fail-safe ＋ 去重（recordViolation）。

用語對照（給管理層）

🧑‍🏫 FDE（訓練師）

建置、訓練、管控 Agent 的人。唯一能讓變更真正生效的角色（TRAINER／OWNER）。

👤 操作者

日常使用 Agent 的員工（MEMBER）。可提案，不可直接生效。

🏭 技能工廠

三入口共用一條管線：① 打字／語音 ② 上傳 ③ 錄製 → 理解 → FDE 確認 → 掛載／版本化。

⑧ Risks & Next

已知限制與下一步

誠實呈現，不粉飾。紅＝阻斷關鍵路徑；黃＝品質／清理項；灰＝路線圖未做。

🔴 高
1. Computer Use 實際執行尚未跑通
computer-use MCP 握手與 tools/list（10 工具）正常，但真正的 tools/call 會 timeout（codex exec 也卡約 10 分鐘無回應）。研判需 Codex／ChatGPT App UI 端確認或特定授權脈絡。詳見 ADR 0005。
  • MCP 握手 OK · 工具列表 OK · 實際呼叫未通
  • 「把錄製變成 Skill」不是 MCP 工具，是 Codex 自己的 record-and-replay + skill-creator 行為 — 我們委派、不自寫翻譯器
🔴 高
2. 錄製 → 技能未端對端實測
因上項阻塞。匯入階段已驗證：origin=RECORDED、停在待確認、redactor 生效。完整「錄製操作 → Skill 可重播」尚待 Computer Use 打通後複測。
🟡 中
3. approveProposal 對 RESTRICTION 是整包 merge
非限制欄位（如 note）可能寫進 restrictions。功能無害（parseRestrictions 忽略未知鍵），建議加白名單。
🟡 中
4. Lesson 表是死 schema
全庫零使用。可刪或併入 ChangeProposal（ADR 0003 已確認不復用 Lesson）。
🟡 中
5. Sandbox 只做寫入圍籬
無 CPU／記憶體配額；claude-in-sandbox 尚未 live 驗證。
🟡 中
6. 語意越矩 severity 門檻未調校
目前為實作預設（僅 HIGH 進佇列），尚未依真實資料調校噪音與漏報。
⬜ 未做
7. 路線圖尚未啟動項目
Browser Use 整合 · 本地 Whisper · 多租戶／計費 · 消費外部 MCP 的 gateway
