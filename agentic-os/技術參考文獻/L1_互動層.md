# L1 互動層（Chat＋畫布/任務看板雙面、語音原語）

**策略**：混合：🟢借用（AG-UI 協議 ＋ assistant-ui/CopilotKit/Vercel AI SDK 等 UI 層 ＋ Pipecat/LiveKit 語音引擎）為主體 ＋ 🔴自研（Interaction Gateway／Event Store／State Plane／Voice Adapter Layer）；本層 🔵採購為零，全數可自架

## 🏗️ 自研開發 Spec

Interaction Gateway (stream-gateway) 為 AG-UI 事件唯一進出口，處理 SSE/WS 連線、斷線後依 afterSeq 續傳、auth、內容 redaction、event replay；前端不得直連後端 Agent Runtime Bus。Chat Plane 與 State Plane (Canvas/Task Board Store) 分離但共用同一 Event Store，State Plane 由 STATE_SNAPSHOT/STATE_DELTA 事件驅動更新，是可編輯的真相來源而非聊天文字的衍生物。Artifact Service 管理版本化文件儲存（metadata DB+S3）、fork/branch；Task Board Service 管理跨 Run 的 durable task 狀態機。Voice Adapter Layer 以 VoiceTurnPolicy/OutputController 抽象介面包裝 Pipecat 或 LiveKit Agents engine。核心資料模型：RunAgentInput（threadId/runId/parentRunId/state/messages/tools/context）、Thread/Run（可帶 parentRunId 形成 sub-agent tree）、Message（parts 為聯合型別，只存 artifactId+version 引用不內嵌全文）、Artifact/ArtifactVersion（每次編輯新增 version、optimistic concurrency）、Task/AgentTask 狀態機（粒度待架構師定稿）、Tool Call 狀態機（proposed→...→succeeded|failed|cancelled）、Event Envelope（含 schemaVersion/seq/idempotencyKey）。

## ❌ 反模式（要避免）

- 不要把 CopilotKit 或 Vercel AI SDK 的內部資料格式當成整個 OS 的跨服務協議——協議層統一走 AG-UI
- 不要靠解析聊天文字 (NLP on chat messages) 推斷任務進度——Task/Board 狀態必須來自結構化 STATE_*/自訂事件
- 不要把 RSC 的 streamUI 當作 durable 或跨 client 的協議邊界——官方標記為 experimental
- Tool call 的 arguments 串流是 partial JSON：不要每個 chunk 都嘗試完整 parse 或 schema validate，正式驗證留到 TOOL_CALL_ARGS_END 之後
- 不要直接 fork Open WebUI 或 LobeHub 作為 L1 基底——兩者授權皆非乾淨 permissive
- 不要讓 CopilotKit Runtime 變成系統的 source of truth——AG-UI 是協議、自建 Event Store 才是唯一事實來源
- Task Board 的 Task 物件不可與 AG-UI 的 STEP_* 混用——Task 是可跨多個 Run、可被人工搬動、可等待 approval 數天的 durable business object
- Agent 生成的可執行內容 (HTML/React/Code) 不可在與 host app 相同 origin 渲染——必須用不同 origin 的 sandboxed iframe
- ACTIVITY_* 事件預設應僅供前端顯示 (client-only)，不應被程式化回灌進下一輪 agent input
- VAD 不能單獨拿來判斷「該不該讓使用者插話/該不該結束回合」——至少要搭配語意層 End-of-Turn 模型或高品質 STT endpointing
- 不要把 TEN Framework/TEN VAD 當核心依賴——其授權為 Apache-2.0 加額外條件，且有 Agora 競業限制字樣
- 不要把任何專案方自己公布的效能數字當成跨框架、跨語言（尤其中文/台灣口音）的 SLA 保證，正式決策前需自建同條件 benchmark
